# Pre-correction table fragments (superseded, do not cite)

These fragments were produced by the original table generator, before the
execution-sandbox defect described in the paper (Section "A Sandbox Defect and
the Re-Scoring Procedure") was found and fixed.

Two problems make them unsuitable for use:

1. The numbers are scored by the defective sandbox, which rejected allow-listed
   modules through their private C accelerators (`bisect` -> `_bisect`) and
   recorded correct programs as `sandbox_violation`. Rates differ by condition.

2. The generator covered only `tab3`-`tab6`. The remaining five fragments
   (`tab7`-`tab10`, `tab12`) are `\todo{}` placeholders, so the corresponding
   numbers in earlier drafts had no traceable source.

They are retained only so the correction is auditable: `tab11_errortax.tex`
here is the file whose `sandbox_violation` row (25.0 / 40.0 / 22.9) was
inconsistent with the value printed in an earlier draft.

Current tables live in `../generated_tables/`, regenerated by:

    python scripts/build_all_tables.py \
        --results results/submission-20260509-223437-rescored \
        --out generated_tables
